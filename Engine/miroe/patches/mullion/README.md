# Mullion patches

On [Mullion](https://github.com/dttdrv/mullion) at the commit in `../../sources.conf` (`mullion`), in order.

| Patch | What it does |
| --- | --- |
| `0001` | The ARM64X link fix from Hadron's `patches/dxmt/0003`, unchanged: link libmingwex first so `__icall_helper_arm64ec` is not defined twice with Wine 11.21+ |
| `0002` | MUMA v2 ported from DXMT (`../dxmt/0001`-`0003`): spares of dynamic resources are trimmed by a thread per command queue, purgeable while idle, and freed under Mullion's memory budget. A purgeable spare leaves the residency heartbeat's set while it is one |
| `0003` | Presents into a top-level window of another process (Chromium's GPU process drawing into the browser process's window, as Steam does): the layer goes into a click-through panel over the owner's Cocoa window, kept just above it. Without it Steam's window is black on WineHQ's winemac.drv |
| `0004` | Keeps those panels in an order nothing fights. Steam flickered because (1) Chromium keeps a second swapchain for the same window and each panel moved itself to just above the owner every 0.1 s, so they swapped places, and (2) Wine keeps owned windows (menus, popups) as Cocoa child windows directly above the owner, so a panel put between them was moved back and the menu's panel went under the main one. An owner window and its process's windows stacked directly above it form a run; all their panels go on top of the run, lowest window first; a window of the run without a panel (drawn by Wine, like a dialog) shows through a hole. One timer, 60 times a second, so a panel follows a dragged window. Measured on the user's Steam: window order the same in 80 of 80 samples with a menu open (before: 43/37), about 0.3 % of the GPU process's samples |
| `0005` | Shows another process's window through winemac.drv's own cross-process swapchain (`CAContextSwapChain`, Wine commit `1a63b0d7c4`, Marc-Aurel Zent, May 2026), the way Chromium does it on macOS: the GPU process exports a layer tree through a `CAContext` and the browser process shows it inside its window with a `CALayerHost`, so the window server draws it as part of the window. No panel any more: it moves, stacks, hides and takes clicks with the window. Such a layer keeps its alpha, as DirectComposition does for Chromium on Windows (Chromium's first frame of an opening popup is transparent black, which an opaque layer showed as a black flash). 0003/0004 stay as the fallback for a Wine without that class. Measured while the window moved: the 0004 panel was off the window in 442 of 1029 samples (up to 5 pt, the flicker while dragging); with 0005 the GPU process has no window and nothing is off (0 of 1041) |

Results are in `../../docs/research-log.md` ("MUMA on Mullion"). LGPL-2.1-or-later like Mullion, written with AI assistance. Mullion's CONTRIBUTING accepts reviewed AI-assisted changes, but nothing here has been submitted.
